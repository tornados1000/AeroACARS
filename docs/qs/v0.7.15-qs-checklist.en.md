## Block A — Phase 1 auto-resume (MSFS or X-Plane)

### A1. Sim disconnect detection

**Setup:** Active flight in cruise. Sim is running.

1. Kill the sim task (simulate a CTD): MSFS Task Manager → End Task / X-Plane SIGKILL
2. **Wait 30 seconds** (= `SIM_DISCONNECT_THRESHOLD_S`)
3. Check the activity log

**Pass criterion:**
- Activity log shows `⏸ Sim disconnected — flight paused. Click "Resume flight" once you have repositioned.`
- Active flight panel shows a pause banner
- **No "PIREP terminated"** in phpVMS live tracking within the next 5 minutes

### A2. Heartbeat in the pause state

**Setup:** Follows A1, sim is killed.

1. **Wait 5 minutes** with the sim killed and AeroACARS open
2. Refresh phpVMS live tracking (browser)

**Pass criterion:**
- PIREP still shows "active" / `updated_at` is current
- AeroACARS log (Settings → Diagnostics) shows at least 5× `PIREP heartbeat sent during pause` entries

### A3. Auto-resume

**Setup:** Sim restarts after A1/A2. Load "Continue Flight" (autosave ~10 min old → ~80 NM drift).

1. Start the sim
2. "Continue Flight" → AeroACARS receives SimConnect/RREF data again

**Pass criterion:**
- Activity log shows `▶ Flight resumed automatically — repositioned X.X nm` (X depending on autosave age)
- For drift > 50 NM: warning level. For > 200 NM: additional notice "Very large reposition X NM. Check whether the correct flight is loaded."
- **NO "Resume flight" click required**
- The position trace on the live map has a gap + a fresh position
- `distance_nm` in the live PIREP does NOT jump up by the reposition distance

### A4. Pause time deducted from flight time

**Setup:** Start the PIREP before takeoff. Take off. 5 min cruise. Then kill the sim.

1. Note the exact wall-clock time: `takeoff_at` to `now`
2. Leave the sim killed for **10 minutes** (beyond `SIM_DISCONNECT_THRESHOLD_S`)
3. Restart the sim, continue flight, fly for 2 more minutes, land, file the PIREP

**Pass criterion:**
- PIREP `flight_time_minutes` = `(landing_at - takeoff_at).minutes - 10` (= pause deducted)
- Sanity check: phpVMS PIREP detail shows a plausible flight time, not 17 min for a 7 min real flight

### A5. Manual resume remains available (fallback)

**Setup:** Active flight. Kill the sim. AeroACARS paused.

1. **Instead** of restarting the sim: click "Resume flight" in the AeroACARS UI
2. Check the activity log

**Pass criterion:**
- Activity log shows `▶ Flight resumed — …`
- Pause block entry in `active_flight.json` (Settings → Diagnostics → show JSON)

## Block B — Phase 2 server session join

### B1. 25-minute gap remains a single session

**Setup:** Active flight, any phase. live.kant.ovh webapp open in browser.

1. Note the `pirep_id` from the AeroACARS UI
2. Kill the sim → AeroACARS pauses
3. **Wait 25 minutes** (beyond `RESUME_WINDOW_MS = 20 min`)
4. Start the sim, Continue Flight → AeroACARS auto-resumes

**Pass criterion:**
- aeroacars-live webapp → pilot history → the flight is **a single row** with `position_count` ≈ pre-pause + post-pause
- Not two separate sessions

### B2. Terminal protection after a filed PIREP

**Setup:** A PIREP was just filed (ARRIVED). The pilot starts a new flight with the same bid (if possible) or observes that accidental replay ticks don't go back to the ARRIVED session.

**Pass criterion:**
- The webapp shows two separate sessions (ARRIVED + new session)
- The ARRIVED session remains unchanged, no `last_seen` updates

## Block C — F5 MSFS pause via `Pause_EX1`

### C1. Esc pause mid-cruise

**Setup:** Active MSFS flight in cruise.

1. **Press Esc** → MSFS menu appears, sim pauses
2. Wait 2 minutes
3. **Press Esc again** → sim runs again

**Pass criterion:**
- Activity log shows after Esc-1: `⏸ Simulator paused — AeroACARS pauses recording.`
- Activity log shows after Esc-2: `▶ Sim pause ended — flight resumed`
- `active_flight.json` contains a new `pause_segments` entry with `duration_secs` ≈ 120 and `reason: "sim_pause"`

### C2. Initial state on connect during pause

**Setup:** MSFS is running + is paused. AeroACARS is **not** open.

1. Start AeroACARS + resume the flight
2. **Check the pause indicator in the UI**

**Pass criterion:**
- AeroACARS immediately recognizes that MSFS is paused (= Pause_EX1 sends initial state on subscribe)
- Activity log shows right after connect: `⏸ Simulator paused`

### C3. Active pause (P key instead of Esc)

**Setup:** Active MSFS flight.

1. Press the **P key** (= active pause with the world still running)
2. Wait 30 s, press P again

**Pass criterion:**
- Same as C1 — `Pause_EX1` triggers regardless of the pause variant. `dwData` hex in the tracing log shows `0x04` (active pause) or `0x01` (full pause)

## Block D — F6 X-Plane pause + replay

### D1. X-Plane pause key

**Setup:** Active X-Plane flight.

1. Press the **pause key** in X-Plane
2. Wait 2 minutes
3. Press the pause key again → runs again

**Pass criterion:**
- Same as C1 — activity log + `pause_segments` entry
- `sim/time/paused` is detected via RREF (X-Plane does NOT need the web API enabled for this)

### D2. X-Plane replay mode

**Setup:** Active X-Plane flight.

1. Activate replay mode (`Ctrl+Space` or similar)
2. Let it run in replay for 30 s
3. Exit replay

**Pass criterion:**
- AeroACARS treats replay like a pause (= `pause_segments` entry)
- Replay time does NOT count as flight time in the PIREP

### D3. Old X-Plane (<12.1) compatibility

**Setup:** X-Plane 11 or X-Plane 12.0.

1. Start a normal flight
2. Press the pause key

**Pass criterion:**
- If `sim/time/paused` is available for the older X-Plane (should be, the DataRef is old): same as D1
- If not: AeroACARS falls back cleanly to the disconnect path after 30 s. No crash, no hang

## Block E — F7 aircraft change warning

### E1. MSFS aircraft mismatch

**Setup:** Active flight with bid "B738". Kill the sim or Esc-pause.

1. In MSFS → World Map → load a different aircraft (e.g. A320neo)
2. "Continue Flight"
3. AeroACARS resumes (auto or via sim-pause resume)

**Pass criterion:**
- Activity log shows a warning entry: `⚠ Aircraft mismatch after resume: sim reports A320, bid expects B738`
- Details in the entry include the note "Cancel PIREP or reload the correct aircraft"
- **Resume proceeds anyway** (no block)

### E2. X-Plane 12.1+ aircraft mismatch (web API on)

**Setup:** X-Plane 12.1+ with web API active (Settings → Network → Web Server / Web API ON). Active flight with bid "A320".

1. Load a different aircraft in X-Plane (Settings → Aircraft → Cessna 172)
2. Resume trigger

**Pass criterion:**
- Same as E1: activity log warning entry with a concrete ICAO comparison
- `aircraft_icao` from the X-Plane web API (`sim/aircraft/view/acf_ICAO`) is compared against the bid

### E3. X-Plane web API off — F7 silent

**Setup:** X-Plane 12.1+ with the web API **disabled**. Active flight.

1. Load the wrong aircraft → resume

**Pass criterion:**
- NO aircraft change warning (= no false positive)
- Resume proceeds normally, pause accumulator counts correctly

## Block G — Smoke tests against the AUA 323 trigger

### G1. Re-trigger of the original scenario

**Setup:** Any mid-to-long flight, MSFS or X-Plane.

1. Start the PIREP, take off, climb, cruise
2. Mid-flight in cruise: **kill MSFS** (simulate a CTD — like AUA 323)
3. **Deliberately wait 23 minutes** (beyond RESUME_WINDOW_MS)
4. Restart MSFS, Continue Flight or "load a new flight at the departure airport"
5. AeroACARS auto-resumes
6. Manually fly the approach + land + file the PIREP

**Pass criterion:**
- live.kant.ovh webapp → pilot history shows **a single session** for this flight
- PIREP flight time = actual time flown (pause deducted)
- `position_count` in the session > 1000 (= recorded continuously, no split)
- Activity log contains exactly one pause segment with `duration_secs` ≈ 1380 (23 min)

**This is the final acceptance test.** If G1 is green, v0.7.15 is release-ready.
